# ВК и дизайнер в онлайн-офисе

Источник задачи: владелец попросил реализовать договорённости из чата «Создание второго мозга» (проект «личная эффективность»). Подтверждено 19.10.2026: сообщество https://vk.ru/autosklad63; первый дизайнер — бесплатные шаблоны с реальными фото.

Ответственные: маркетолог — тема, бриф и текст; дизайнер — макет; менеджер продаж — факты товара; ВК-агент — публикация и передача обращений; разработчик — постоянная среда и доступы. Критерий готовности автономной цепочки: материал проходит все этапы без ручного переноса, реальный пост получает проверенную ссылку, обращение попадает в нужный журнал, повтор не создаёт дубли и сбой не вызывает слепой повтор публикации.

## Что работает

- `/#studio` (хеш `#studio`) — брифы, локальная очередь этапов, загрузка JPG/PNG/WebP до 12 МБ, шаблон PNG 1080×1080 или 1080×1350, текст поста и экспорт брифа JSON.
- Фото размещается целиком, без генерации деталей изделия. На сервер фото не отправляется. После перезагрузки его выбирают заново.
- Брифы сохраняются в localStorage текущего браузера. Это не серверная очередь и не совместное хранилище сотрудников.
- До передачи проверяются факты и права на фото. Изменение текста/макета сбрасывает готовность. «Готово для ВК» не означает публикацию.
- Карточка менеджера продаж отражает проверенный MAX → подтверждение → распределение чехлов и ковров. Новая студия не изменяет этот поток.

## Блокеры автономного режима

1. Браузерная политика безопасности заблокировала vk.ru. Не обходить запрет другим браузером, прокси или альтернативными адресами. Настройки сообщества открывает владелец вручную.
2. Нет настроенных серверных полномочий VK API и проверенного события сообщения. Токен не вводить на сайте и не передавать в чат/Git.
3. Нет постоянной общей очереди контента и серверного исполнителя дизайна. Нужны хранение реальных фото, версия макета, политика автоматического допуска и журнал ошибок.
4. Автопубликация, расписание и автоматическая передача обращений ВК в продажи не включены. Следующий шаг — подключить API в защищённой среде, затем проверить одну согласованную публикацию и одно обращение.

Публикацию сайта не путать с публикацией постов в соцсети. Доступ онлайн-офиса сохраняется только владельцу.

## Приёмник Callback API

На сервере MAX подготовлены /vk/webhook и /vk/health. Переменные: VK_COMMUNITY_TOKEN (ввод владельцем), VK_GROUP_ID, VK_CONFIRMATION_CODE, VK_CALLBACK_SECRET (не менее 32 символов). /vk/health выдаёт только признаки настройки; наличие ключа не означает проверку ключа через API. Подтверждение Callback ограничено group_id; входящие события требуют секрет. На этапе callback-setup сервер только подтверждает получение, не хранит переписки и не отправляет ответы или посты. Следующий критерий — подтверждение адреса и одно реальное message_new с проверенным секретом.
