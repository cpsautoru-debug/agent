# Проверка Ozon Profit SKU и общих расходов — этап 22.11.2026

## Что изменилось

Действующий финансовый монитор АвтоСклад63 читает четыре источника: себестоимость WB, справочник товаров Ozon, документ `costs` сервиса Ozon Profit и документ `expenses` того же сервиса. PR добавляет **только чтение и проверку**, без новых D1-таблиц и без изменения работающего Cron.

### Не путать 36 версий себестоимости с 36 товарами

Каждая запись Ozon Profit привязана к SKU и датам действия. Один SKU может иметь несколько исторических версий. В разделе «Ozon Profit: уникальные SKU и товары без карточки в справочнике» показываем:

- общее число *версий* `costs.entries` отдельно от числа уникальных SKU;
- список SKU, которые есть в Profit, но отсутствуют в вспомогательном `ozon_cost_entries` — **модель/артикул продавца неизвестны**, цены не переносятся в WB;
- список SKU, которые есть в справочнике, но отсутствуют в Profit;
- совпадения только по точному SKU, **не по похожему названию**.

Ozon Profit может содержать подтверждённые затраты и не содержать карточку товара. Чтобы связывать такой SKU с WB, нужен проверенный справочник SKU → карточка товара (модель/материал/комплектация), а не только финансовая цена.

### Контроль общих расходов

В том же мониторе отображаются заданные в документе расходов Ozon Profit суммы как **значения документа, а не фактические выплаты**. Показатель не участвует повторно в расчёте WB или объединённого P&L.

Выявляем только потенциальный, не доказанный дубль, когда в документе есть доставка кожи/материалов и в версиях себестоимости Ozon Profit `leatherDeliveryIncluded=true`. При `null` предупреждаем о неизвестном составе. Для других общих статей показываем, что распределение между каналами ещё не утверждено. Ни одна сумма не может вычитаться вторично автоматически.

### Приёмка

1. Войти как владелец в `https://autosklad63-office-staging.pages.dev/#wbFinance`.
2. Нажать «Обновить источники», раскрыть «Ozon Profit: уникальные SKU и товары без карточки в справочнике».
3. Сверить фактические показатели: число версий Ozon Profit, уникальные SKU, Profit-only SKU, catalog-only SKU и пересечения. **Не выводить количество SKU из количества версий**.
4. Прокрутить к общим расходам: «Доставка кожи» должна требовать проверки на дубль с себестоимостью, если `leatherDeliveryIncluded=true`; если состав неизвестен, это должно быть явно отражено.
5. Проверить, что первая себестоимость WB «веста №2» остаётся предварительной, история Ozon Profit, расходы, финансовые операции и работающие Worker/Cron не изменились.

### Следующие фактические блокеры

- Реальный Ozon API каталог SKU → карточка товара с подтверждёнными атрибутами и датами; нельзя считать все версии `costs` отдельными товарами.
- Подтверждение источников и распределения накладных расходов; доставка материала, включённая в себестоимость, не должна повторно попадать в накладные.
- Связь платежных/рекламных документов по WB и Ozon и налоговая база по соответствующим плательщикам.

Только после этих пунктов будет обоснован полный P&L по артикулам и бизнесу.
