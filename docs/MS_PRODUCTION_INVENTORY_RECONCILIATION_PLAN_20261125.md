# АвтоСклад63 — приоритетный план полного запуска учёта МойСклад → Онлайн-офис
Дата: 2026-11-25. Статус: план подтверждения и первичный технический аудит, НЕ завершённое внедрение.

## Цель владельца
В онлайн-офисе видеть актуальные остатки материалов по метрам, кроя по моделям/размерам, готовой продукции по SKU и двум складам; входящие заказы Ozon/WB/Яндекс, их производственные этапы, поступление на склад, сборку, отгрузку и возвраты. Источник учётных документов — «МойСклад»; API без ручного внесения номеров заданий; отчётность с контролем происхождения данных.

## Безопасность / правила
- **Не обнулять и не удалять заказы/остатки/складские документы.** Период начала нового учёта задаётся отдельной датой контрольного среза, старые документы остаются доступными. До исправлений: экспорт/резервная копия, фиксация неизменяемых ссылок на исходные документы, dry-run.
- Ни одна исправительная операция в МойСклад не выполняется автоматически без контрольной сверки её последствий. Устранять причину минуса, а не «подгонять» склад.
- Единицы метража и материалы проверяются физически: метры vs погонные метры, миллиметры, рулоны и штуки; двойное списание кроя и техкарты не допускать.
- Нельзя считать исторический неполный этап текущим заказом. Статусы заказов WB/Ozon/Яндекс определяются реальными интеграционными связями, не угаданы из названий.
- Для каждой панели отдельно указать: время последнего обновления, источник, полноту загрузки; неиспользуемое значение = Н/Д, не ноль.

## Этап 0. Неприкосновенная база и диагностика (старт)
1. Подтвердить 2 склада и названия/ID из API, карту товарных групп, единицы измерения; выгрузить текущее состояние справочников, техкарт и оприходований/списаний/перемещений в read-only отчёт.
2. Сверить текущие физические остатки и МойСклад на обоих складах по группе критичных материалов, кроя и готовых изделий; обнаружить минусы, документы-источники и неверные единицы.
3. Зафиксировать дату контрольного среза (без сброса истории). Обнаружить импортные дубли заказов, повторное проведение и неверное распределение на склады.

Критерий: реестр расхождений по SKU+склад+единица+источник с приоритетом и корректным действием, без мутаций.

## Этап 1. Техкарты и нормы расхода
1. Проверить модели Vesta / Vesta Cross / Priora / Samara / Iskra и все фактически действующие комплектации; версия, номер техкарты, изделие, материал, единица, количество и коэффициенты выхода.
2. Сверить нормы метража исходной экокожи, алькантары, перфорации, Pegas/подкладки и вспомогательных материалов. Проверить, не включается ли кожа дважды: в раскрой и финальную сборку.
3. Этапы: материал → крой (заготовки/детали по размеру и модели) → пошив → ОТК → готовый комплект. Отходы отдельно; неизбежные технологические потери — документированная норма.
4. Проверить отрицательные остатки причинно: отсутствующее поступление, неверная техкарта/материал, единицы, дважды проведённый этап, перемещение не на тот склад, дата документа.

Критерий: контрольный производственный прогон по 1 комплекту каждой тестовой модели даёт верные метры, крой и готовую продукцию без лишних списаний и минусов.

## Этап 2. Потоки заказов маркетплейсов
1. Подтвердить, какие источники уже создают в МойСклад customerorder: Ozon, Wildberries, Яндекс «САД», статус FBO/FBS и внешний идентификатор/корреляция.
2. Idempotency: один заказ маркетплейса не превращается в 2 заказа после повторной синхронизации. Отмены/возвраты отдельными операциями.
3. Связь customerorder ↔ производственное задание ↔ изделие/SKU/вариант/размер ↔ резерв ↔ фактический выпуск ↔ shipment/отгрузка.
4. Раздельные статусы: получен, ожидает производства, раскрой, пошив, ОТК, готов на складе, зарезервирован, отгружен, отменён/возвращён. Не переводить статусы без подтверждённых документов.

Критерий: 3 тестовых сквозных заказа из реальных каналов без дублей, без неверного резерва, с верной схемой FBO/FBS.

## Этап 3. Два склада и балансы
1. Материалы (метры) по складам и физические перемещения.
2. Крой (штуки комплектующих, модель, конфигурация) по складам/этапам.
3. Готовая продукция (штуки комплектов) по SKU, доступно/резерв/в пути.
4. Балансовый контроль: начало + поступление + выпуск + перемещение_вход − расход − перемещение_выход − списания ± корректировки = конец; отдельная диагностика отрицательных остатков и неизвестных единиц.

Критерий: контрольные группы по 2 складам сходятся с МойСклад и физическим срезом; расхождения документированы.

## Этап 4. Интеграция онлайн-офиса
- Читаем из МойСклад реальные заказы, техкарты/выполнение этапов, остатки и перемещения. Использовать курсор, ограничение API, API-ошибки, повторные попытки; не считать историю живой очередью.
- D1 как журнал снимков/сверок: source_id, updated, warehouse, SKU, units, raw totals, sync status, discrepancies; не подменяет МойСклад как источник истины.
- На панели: «Заказов ждёт», «В раскрое», «В пошиве», «ОТК», «Готово», «Отгружено» + Остатки материалов в метрах, крой, готовые комплекты, два склада, последнее обновление, ошибки.
- Без лишних диагностических абзацев на главном экране; техническая детализация за отдельной кнопкой.

## Этап 5. Рабочий регламент и приёмка
- Макс: раскрой по производственному заданию; швеи: выполнение пошива; Ирина: ОТК/упаковка; Илья: контроль учёта и устранение расхождений; руководитель: ежедневная панель.
- Точечная проверка входа, 2 складов, резерва, списаний, выпуска и отгрузки; реальный заказ прослеживается до товара.
- Финальный отчёт: подтверждённые остатки, процент покрытия техкарт, % синхронизации заказов, число минусов, число дублей, последняя успешная синхронизация.
