# Оркестратор · read-only пилот

Подключается к существующему облачному онлайн-офису в ветке `feature/marketplace-agents-staging`.
Это **первый управляемый маршрутизатор и языковой аналитик**, ещё не автономная система
из девяти исполняющих агентов. Финансовые и производственные данные не меняет.

## Как работает

- Доступ через действующий Google owner session из `office_authorized_users`.
- `GET /api/orchestrator/chat` — проверка подключения (ключ не возвращается).
- `POST /api/orchestrator/chat` с JSON `{"message":"..."}` — один вопрос, до 900 символов.
- Маршрутизатор выбирает WB, Ozon или оба по вопросу.
- Переиспользуются проверенные GET-обработчики `/api/wb/unit-economics` и `/api/ozon/profit`.
- Источники с ошибкой помечаются как недоступные, без придумывания нулей и остатков.
- В модель уходит **только сокращённый снимок** финансовых агрегатов и до 12 товаров.
- Ответ формирует OpenAI Responses API; `store:false`, один вызов, ограничение выходных токенов.
- История чата не сохраняется, никакие D1-таблицы или бизнес-операции не изменяются.

## Для включения

1. Протестировать в **отдельной ветке/preview**, не трогая production и рабочие базы.
2. Развернуть файлы `web/office` и `functions` по принятому процессу проекта.
3. На нужном Pages-проекте: **Settings → Variables and Secrets → Add**.
4. Задать **зашифрованный Secret** `OPENAI_API_KEY` — ключ OpenAI API
   с включённым биллингом и контролем расходов в проекте OpenAI.
   Не вводить ключ в браузере, GitHub, чат или файл проекта.
5. Необязательно: `OPENAI_ORCHESTRATOR_MODEL` — доступный модели API ID;
   по умолчанию `gpt-4.1-mini`.
6. Открыть офис под владельцем, вкладку **ИИ-Оркестратор**, проверить
   `GET /api/orchestrator/chat` и задать вопрос про WB/Ozon.
7. Проверить ответ по исходным финансовым разделам и оценить фактические расходы.
8. Только после тестов вручную утвердить публикацию.

## Границы и риски

- У Оркестратора **нет** права на запись, рекламу, публикации или производство.
- Нет API для сегодняшних заказов, текущих остатков и вчерашнего чистого P&L.
- WB API выдаёт агрегат по завершённым отчётам, не по календарному месяцу.
- Ozon `profit` может быть неполным; прибыль не подтверждается без затрат, налогов и сверки.
- Финансовые агрегаты отправляются в OpenAI API; требуется юридическая и договорная
  проверка передачи конфиденциальных данных.
- Для промышленного режима нужны постоянные лимиты расходов, журнал,
  идемпотентность задач, мониторинг, тесты безопасности.
- Нет долговременной памяти, автоматического фонового исполнения и девяти специализированных агентов.

## Минимальная приёмка

- Без owner cookie: 401. С чужим Google sub: 403.
- Без `OPENAI_API_KEY`: 503, не отправлять данные.
- POST с другого Origin, слишком длинный запрос и не-JSON отклоняются.
- При ошибке одного источника ответ не должен утверждать, что данных нет в бизнесе.
- В ответе нет заявлений о подтверждённой чистой прибыли при `null`/incomplete.
- Ответ модели экранируется в UI с `textContent`, не как HTML.
- Старые разделы WB, Ozon, производства и авторизация остаются работоспособными.
