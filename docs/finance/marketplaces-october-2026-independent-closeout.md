## Методика

2. Удержания и услуги маркетплейса (учитывать ровно один раз).

5. Статус: проверенный результат после известных прямых затрат **≠ чистая прибыль**.

- **Критическая граница:** реестр D1 хранил ID отчётов, но не детальные нормализованные продажи/возвраты по SKU и не полный реестр внешних расходов. Статус `DONE` доказывает сформированность отчёта, **а не** полную сверку операций или чистую прибыль.
- Добавлено автоматическое формирование и серверное хранение **без данных покупателей**: владелец-авторизованный браузер извлекает SKU, количество доставленных и возвращённых товаров, статусы и подтверждённые себестоимости, затем передаёт ограниченный месячный снимок в `/api/yandex/evidence-snapshot`; сервер сравнивает все 5 ID с записями D1. Обновление с главного дашборда и из раздела Яндекса, без кнопки ручной загрузки.
- `owner_browser_audited_summary` является архивом управленческой сверки, **не налоговым или банковским актом**. Никакая сумма не объявляется чистой прибылью автоматически без подтверждения оставшихся расходов и налогового регистра.
- Если в таблице отсутствуют идентичные SKU, неполны количества/возвраты либо налоговый период — закрытие остаётся заблокированным, а неизвестные значения **не заменяются нулями**.

## Приёмка этапа
- Неизменные исходные Ozon/WB суммы независимо подтверждены запросами к D1 (без записи в основные финансовые таблицы).
- Пользователю не нужно заново загружать имеющиеся октябрьские отчёты, вручную переносить суммы или обновлять Cloudflare; новая версия финансового раздела сама собирает безопасные агрегаты из уже доступных архивов при открытом офисе.
- Для принятия `netProfitVerified=true` по каждой площадке нужны подтверждённые **банковские/налоговые и внешние рекламные источники**, включая дату фактического налогового дохода. Только после этого возможна проверяемая чистая прибыль.
