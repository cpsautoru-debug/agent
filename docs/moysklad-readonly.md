# МойСклад: первый этап, только чтение

Ответственный: разработчик интеграции. Приёмка и разрешение на развёртывание — владелец.
Вход: действующие MAX/VK/Sheets Bridge, JSON API 1.2, структура рабочей таблицы и токен в Render.
Результат: изолированный GET-клиент, защищённые маршруты, подготовка сопоставлений и локальный отчёт без записи.
Критерий готовности этого PR: тесты проходят, секретов и коммерческих строк в Git нет, main и производство не изменены. Это не запуск синхронизации.

## Клиент и защита

`apps/max-agent/moysklad.mjs` использует только `process.env.MOYSKLAD_API_TOKEN`. Адрес фиксирован: `https://api.moysklad.ru/api/remap/1.2`. Только GET; перенаправления запрещены. Токен, тело ошибки сервиса и исходные исключения не выводятся в ответы/логи.

| Ресурс клиента | API |
| --- | --- |
| assortment / products / variants / bundles / units | entity/assortment, product, variant, bundle, uom |
| stores / stock / stockByStore | entity/store, report/stock/all, report/stock/bystore |
| purchaseOrders / supplies | entity/purchaseorder, entity/supply |
| customerOrders / demands / losses | entity/customerorder, entity/demand, entity/loss |
| processingOrders / processings / processingPlans | entity/processingorder, entity/processing, entity/processingplan |
| productionTasks / productionStageCompletions | entity/productiontask, entity/productionstagecompletion |

Доступны страницы, полное ограниченное чтение, чтение отдельного документа и разрешённых вложенных коллекций позиций/материалов/продукции. Наличие функций не означает наличие данных и прав в конкретном аккаунте.

Пагинация: limit до 1000, проверка offset/nextHref/повторных ID/изменения размера выдачи; чужой nextHref не исполняется. Полное чтение по умолчанию ограничено 100 страницами, 10 000 строками и 32 МиБ, ответ — 8 МиБ. Превышение или неполная выдача завершаются ошибкой. Последовательная очередь, промежуток 500 мс, максимум 25 ожидающих запросов. Тайм-аут 15 секунд, до двух повторов только 429/502/503/504 с учётом заголовков задержки; слишком долгая задержка возвращается оператору. Эти лимиты локальные, не обещание квоты МойСклада.

Обязателен gzip. Номенклатура запрашивается с `assortmentWithoutStock`, остатки отдельно. В отчёты остатков добавляется `stockMode=all`, а для stock/all также `quantityMode=all`. Дату остатка задают внутри `filter=moment=...`, не отдельным параметром.

Новые маршруты `/api/moysklad/connection` и `/api/moysklad/<ресурс>` выключены, пока не задан отдельный `MOYSKLAD_READ_API_KEY` длиной минимум 32 символа. Он должен быть случайным и отличаться от токена МойСклада. Авторизация: `Authorization: Bearer <ключ чтения>`, сравнение хешей постоянной длины. Нет авторизации через URL, открытого CORS или кэширования. HTTP-страница ограничена 100 строками; массового публичного экспорта нет. Создание сервера не выполняет запросов в МойСклад.

## Подготовленное сопоставление

Полная схема и проверяемые заголовки — `SHEET_MAPPING` в `moysklad-reconcile.mjs`. Колонки указаны буквами Google Sheets.

| Лист | Предмет / количество / единица | Назначение | Формульные колонки, не трогать |
| --- | --- | --- | --- |
| Остаток | A / F / B | Физический остаток по подтверждённому складу | C:D:E:F:G |
| Приход | C / E / D | Приёмка supply и её позиции, не заказ поставщику | G |
| Раскрой | B / D / E | Выпуск кроя по документу производства | C:G:H |
| Пошив | B / C / D | Выпуск готового изделия | F:G |
| Комплектации | A, материал C / D / E | Нормативная спецификация | F:H |
| Техкарты | A, материал C / D / E | Нормы материалов и операций | H |
| Инвентаризация кроя 20.10 | B / D, частичные E / явно заданная | Датированный физический пересчёт, заголовок в строке 4 | Не выявлены |

Совпадение названия даёт только кандидата. Для сравнения нужны одобренные владельцем UUID номенклатуры, склада и единицы, точное название строки, её номер и время снимка. Конвертация единиц автоматически не выполняется. Отсутствующий остаток не считается нулём. Частичные комплекты требуют ручного разбора. Сравнивается `stock`, а не свободный остаток после резерва.

Числовая сверка реализована только для «Остаток» и инвентаризации. Операционные листы и нормы требуют связи с конкретными документами/позициями/спецификациями; их строки не суммируются в новый расход. Реальные UUID ещё не сопоставлены. Историческую инвентаризацию нельзя сравнивать с сегодняшними остатками: времена снимков с часовым поясом должны совпадать. Пагинация не является транзакционным снимком: источник может измениться и без изменения числа строк; перед решением требуется повторная проверка периода.

## Локальный отчёт

Команды из корня репозитория:

```powershell
node apps/max-agent/moysklad-report.mjs --probe
node apps/max-agent/moysklad-report.mjs --input private/moysklad/input.json
```

Вход и результат находятся только в игнорируемой `private/moysklad/`; не прикладывать их к PR. Результат содержит коммерческие данные. Права локальной папки на Windows проверяет оператор; Unix mode не заменяет Windows ACL.

Формат входа: `sheetSnapshot: {spreadsheetId, asOf, sheets:[{title, asOf, rows}]}`, `catalogSnapshot: {complete:true, rows}`, `stockSnapshot: {complete:true, asOf, rows}`, `bindings: [...]`, `documents: [...]`, `ledger: [...]`. `rows` листа включает заголовки и эффективные значения, сохраняя номера строк; вместо вычисленного числа нельзя передавать текст формулы. Для binding обязательны `sheet`, `row`, `sheetItem`, `approved:true`, `assortmentId`, `storeId`, `uomId`, `sheetUnit`, `asOf`. Синтетический пример есть в тесте `moysklad-reconcile.test.mjs`.

Экспортёр Google Sheets и автоматическое получение такого снимка в этот этап не входят: требуется отдельный доступ только для чтения или проверенный приватный экспорт. Сейчас отчёт создаётся только по явно переданному снимку; ни таймеров, ни синхронизации, ни расчёта зарплат нет.

## Повторная обработка и двойное списание

Отчёт проверяет идентичность `accountId:type:id`, хеш содержимого, повтор документа, изменение версии и признак проведения. Возвращает предлагаемый журнал проверки, но не помечает документ обработанным. `writeOperations` всегда пуст.

Перед будущей записью нужен постоянный транзакционный журнал с уникальным ключом аккаунт/тип/документ/позиция/операция, сохранением внешнего ID и подтверждения записи. Изменённый документ требует отдельного решения, а не повторного списания. Выпуск и расход из одного производственного документа нельзя списывать ещё раз через «Раскрой»/«Пошив». Текущий обзорный журнал не является готовой гарантией идемпотентности будущей записи.

## Развёртывание: только после подтверждения владельца

1. Проверить PR и CI. Зафиксировать текущую рабочую ревизию Render и способ отката. Если слияние и запуск разрешены отдельно, заранее учесть автодеплой main; не сливать до разрешения на запуск.
2. По отдельному разрешению добавить только новый случайный `MOYSKLAD_READ_API_KEY` через секреты Render. Не менять существующие переменные. Существующий токен должен принадлежать пользователю с минимальными правами чтения; сам GET-клиент не ограничивает права этого токена в других приложениях.
3. После разрешения объединить PR и выполнить согласованный деплой. Этот PR самостоятельно этого не делает.
4. Проверить прежние health/connection MAX и VK, затем защищённый connection МойСклада и по одной ограниченной странице нужных ресурсов. Успех connection проверяет только чтение складов; остальные права проверять отдельно. Не отправлять ключ в чаты/URL/логи.
5. Устранить непостоянную готовность Bridge; обеспечить приватное чтение Google-листов, подтвердить UUID/склады/единицы/период, сформировать и согласовать отчёт о расхождениях. Даже после деплоя запись и расписание не включаются.
6. При регрессии вернуть предыдущую ревизию сервиса. Отсутствие нового ключа закрывает новые маршруты; данные МойСклада и таблицы откатывать не требуется, поскольку интеграция их не изменяет.
