# MAX → Google Sheets: тестовый стенд

Ответственный: инженер интеграций. Вход: отдельный тестовый MAX-бот, синтетические TEST-* позиции и отдельная таблица стенда. Критерий: реальные команды владельца доходят до двух тестовых листов, количественная сверка совпадает, повтор не увеличивает результат.

## Границы

- Ветка: `feature/max-packing-sheets-staging`; main не изменяется.
- Render: только `autosklad63-max-packing-test`, отдельный бот и переменные MAX_TEST_*.
- Таблица: `1x3B-6sdabZNNHCpy8la7Oqwgja7yBjU1G0n1ku0kMoI`.
- Единственные листы записи скрипта: «MAX тест — события» и «MAX тест — сверка». Остальные вкладки копии не используются обработчиком.
- Приёмка водителем не является приёмкой маркетплейса. Складские списания и зарплата не выполняются.

## Выполненные проверки

22.10.2026 подтверждены `/health` 200 sandbox/ready, ветка Render и commit `58ec538`, Live. Веб-приложение GAS доступно; подписанный пустой запрос отвергнут как bad-test-event, что подтверждает прохождение проверки HMAC без записи.

Через личный диалог владельца с тестовым ботом выполнены производство 3 комплектов чехлов и 2 комплектов ковров, упаковка по 2 каждой позиции, передача в одну смешанную отгрузку и подтверждение водителем. Сверка ожидает: чехлы — 3 изготовлено, 2 упаковано/передано/принято, остаток 1; ковры — 2 изготовлено/упаковано/передано/принято, остаток 0. Остальные три тестовые позиции остаются нулевыми. Успешных производственных событий — 7; переключения ролей и отказы в экспорт не входят.

Проверены отказ повторному ID упаковки, неверной роли приёмки и повторной приёмке закрытой отгрузки. На действующем GAS отдельно повторено уже записанное событие: duplicate=true без новой строки; изменённое количество при том же ID отклоняется event-conflict.

## Исправление

Ранее GAS считал любой существующий ID успешным повтором, не сравнивая содержимое. Теперь значимые поля проверяются до записи. Точный повтор по-прежнему восстанавливает производную сверку после частичного сбоя. Исправление опубликовано в существующем тестовом Apps Script, версия 2, с прежним URL и правами.

Добавлены четыре VM-теста реального GAS-кода: полный цикл, частичный сбой сверки и повтор, неправильная подпись/роль/отгрузка, конфликт события. Оба набора тестов мостика добавлены в CI и package test. Полный локальный набор: 127 тестов, 127 успешно. Независимая проверка исправления не выявила важных замечаний.

## Что ещё ограничивает надёжность

1. Текущий Render Free хранит авторитетный журнал бота в `/tmp`. Перезапуск/развёртывание может потерять локальное состояние и неотправленные события. Таблица хранит уже подтверждённые события, но автоматического восстановления бота из неё пока нет. Не считать этот стенд готовым к реальному ежедневному учёту.
2. При недоступности GAS бот может подтвердить локальное действие раньше записи в Google. Поллер повторяет доставку каждые 30 секунд, пока экземпляр работает; это не гарантия сохранности после аварии.
3. Таблица рассчитана на одну синтетическую сессию. Нельзя просто начать новую сессию с теми же ID операций поверх существующего журнала. Старые строки не удалять для устранения конфликта.
4. Авторазвёртывание тестового Render выключено. Runtime сервера не изменён этим исправлением GAS; перезапуск для него не нужен и намеренно не выполнялся.

Следующий обязательный этап перед внедрением: постоянное хранилище журнала/очереди либо подтверждение действия только после надёжной облачной записи с восстановлением состояния из неё. Затем контролируемый тест перезапуска и недоступности Google. Для платного диска или переноса хранилища требуется отдельное решение владельца; покупки не выполнялись.

Использовать новые уникальные ID операций, соблюдать роли alexandra → irina → dmitry. После операции дождаться ответа бота и до 30 секунд поллера, затем проверить ID события в журнале и ровно одно изменение сверки. Не перезапускать сервис и не очищать журнал в рамках обычной проверки.
