# Issue #108: утверждённые связи и ручные исключения

Область: существующий staging-офис, только владелец. Не создаёт документов МойСклад.

- `saved-sku-confirmation.mjs`: выбор активного/требующего проверки SKU,
  ограниченный живой поиск, явное сохранение утверждённого UUID через прежний
  `/api/ms/order-sku-links`. Никаких автоматических связей по названию.
- `orders-stock-match.js`: необязательный `nameQuery` только для одного валидного
  `entries`-элемента; один GET ассортименту, максимум 20 строк, ограниченный ответ.
  Частичная выборка явно обозначена и не доказывает отсутствие товара.
- Авторизация владельца, Origin, проверка UUID и запрет перезаписи прежнего
  соответствия сохранены. Ключи не менялись.
- `manual-item-policy.mjs`: точное исключение WB «Пламя1». Заказ виден отдельно,
  сопоставление со складским товаром запрещено, численный пошив не рассчитывается.
- Первая страница очереди по-прежнему ограничена 150 строками. Текущие кандидаты
  основного Ozon, магазина «Сад» и WB показаны перед историей. Это только порядок
  отображения; свежесть и полнота источников проверяются прежними правилами.
- Ручное исключение читается отдельной ограниченной выборкой с признаком полноты,
  чтобы история других каналов не скрывала его за пределами первых 150 строк.

Проверки: 38 целевых тестов (синтетика), сборка Pages Functions. В тестах проверены
GET-only upstream, авторизация, ограничение живого поиска одним SKU, отсутствие
автоматического утверждения, запрет перезаписи связи, ручной WB, сохранение
текущих кандидатов при более чем 150 исторических строках.

Границы результата: учётный остаток не доказывает физический запас. Полный обход
заказов МойСклад не доказывает все открытые обязательства маркетплейсов. Статус
Ozon awaiting_deliver не превращается в производственную потребность. Исторические
заказы и закрытые производственные задания не объявляются текущей очередью.
Никаких изменений финансов, техкарт, остатков, токенов, привязок и Cron.
