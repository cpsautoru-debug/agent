# АвтоСклад63 — монитор производства «МойСклад»

Статус: staging. Источник данных — «МойСклад» JSON API 1.2, чтение через Cloudflare Pages Functions. Google Таблица не участвует в мониторинге производства.

## Что работает
- GET /api/ms/production-check: одно защищённое чтение.
- GET /api/ms/production-feed: пять заданий по дате за запрос, offset=5,10,... (постранично) либо точный number=00737.
- GET /api/ms/production-stages?taskId=UUID: один запрос на выбранное задание, агрегирование по позициям и этапам без двойного счёта.
- Интерфейс /#production показывает списки и кнопки «Этапы и факт»; браузер при открытом разделе обновляет список не чаще одного раза в 10 минут. При закрытой вкладке Cloudflare Cron не выполняет синхронизацию.
- Показ времени API (МСК, UTC+3) в бизнес-часовом поясе Europe/Samara (UTC+4). Переход дня проверен отдельным тестом.

## Безопасность
- Проверка действующей сессии владельца verifySession и разрешённой записи роли owner в D1. Чтение API из браузера напрямую запрещено.
- Секрет MS_API_TOKEN только в Cloudflare; не отправлять токен в запросах/чат/логи.
- В «МойСклад» всегда только GET, нет POST/PUT/DELETE и нет автоматических изменений D1.
- Ограничения: 5 строк/запрос к списку, один запрос этапов за нажатие, максимум 50 этапов на задание, ограничение ответа, тайм-аут 25 секунд, без автоповторов.
- Никакой периодический воркер Cloudflare, Google Таблица, Ozon или WB не изменялись.

## Что означают числа
- totalAllTime — все документы «Производственные задания» в базе, не текущий портфель.
- documentPosted — факт проведения документа, не завершение изготовления.
- deliveryPlannedMoment — плановый срок, когда он задан в «МойСклад».
- plan — сумма плановых количеств по позициям одного задания, без суммирования каждого производственного этапа повторно.
- finishedFinalStage — сумма выполненного объёма на последнем этапе каждой позиции. Это не отгрузка.
- Если позиции смешивают разные единицы измерения, сложение количеств условно. До получения единиц измерения в UI используются «ед.», а итог нельзя считать количеством комплектов.
- ms_stages_unverified означает неполные/неожиданные данные; нельзя заполнять нулями отсутствующие показатели.

## Известные ограничения и контроль
- Поиск номера через API filter=name=... требует фактического подтверждения на реальном задании после публикации.
- Пять последних и постраничный список — не список всех незавершённых. Критичные задания из прошлых дат надо открывать отдельно по номеру.
- Исполнители швей/ОТК, сроки отдельных операций, остатки материалов и контроль задержек по всем активным заданиям здесь ещё не подтверждены.
- На одно задание более 50 строк этапов предусмотрен отказ с безопасным кодом, а не неполный итог.
- Контрольная точка: №00737 на 20.11.2026 — план 3, заключительный этап 0, пять этапов по нулю (проверено владельцем). Сравнить после изменений.
- Полный производственный контур (заказ покупателя → задание → выполнение → готовая продукция/отгрузка) разрабатывать только после сверки схемы данных, без двойного учёта.

## Откат
При ошибках откатить только последнее изменение в ветке feature/marketplace-agents-staging / Cloudflare Pages. Не вращать токены, не откатывать данные D1 и не затрагивать WB/Ozon.


## Поэтапная сверка незавершённого производства (аудит страницы)
- Кнопка «Проверить 5 заданий» запускает вручную, только при открытом разделе, до пяти последовательных GET вызовов существующего owner-only /api/ms/production-stages?taskId=UUID для видимых документов (при точном поиске может быть один).
- Расчёт для проверенного задания: plan - finishedFinalStage > 0 ⇒ незавершено; = 0 при непротиворечивом выполнении каждого этапа ⇒ завершено; иначе не подтверждено.
- firstUnfinishedStage — первый этап с done < plan по агрегированному результату. Это диагностический признак, не подтверждение фактической очереди/ответственного.
- Три состояния строго раздельно: незавершено, завершено, не удалось подтвердить. Ошибки/отсутствующие строки не превращаются в ноль.
- Статистика и таблица только текущей страницы; при переходе на другую страницу очищаются. Нет таблицы или постоянного хранилища проверок, нет полной сводки 740 документов.
- Если вкладка закрыта во время проверки, новые запросы не начинаются после завершения текущего. Запросы выполняются последовательно, без автоповторов.
- Цель следующего этапа: обоснованная автоматическая сверка всей незавершёнки по API с контролем полноты и нагрузки, только после оценки оптимальных фильтров. Сейчас нет доказательства серверного фильтра, возвращающего все незавершённые документы одной выборкой.
