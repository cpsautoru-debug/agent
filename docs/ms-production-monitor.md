# АвтоСклад63 — монитор производства «МойСклад»

Статус: staging. Источник данных — «МойСклад» JSON API 1.2, чтение через Cloudflare Pages Functions. Google Таблица не участвует в мониторинге производства.

## Что работает
- GET /api/ms/production-check: одно защищённое чтение.
- GET /api/ms/production-feed: пять заданий по дате за запрос, offset=5,10,... (постранично) либо точный number=00737.
- GET /api/ms/production-stages?taskId=UUID: один запрос на выбранное задание, агрегирование по позициям и этапам без двойного счёта.
- Интерфейс /#production показывает списки и кнопки «Этапы и факт»; браузер при открытом разделе обновляет список не чаще одного раза в 10 минут. При закрытой вкладке Cloudflare Cron не выполняет синхронизацию.
- Показ времени API (МСК, UTC+3) в бизнес-часовом поясе Europe/Samara (UTC+4). Переход дня проверен отдельным тестом.

## Безопасность
- Проверка действующей сессии владельца verifySession и разрешённой записи роли owner в D1. Чтение API из браузера напрямую запрещено.
- Секрет MS_API_TOKEN только в Cloudflare; не отправлять токен в запросах/чат/логи.
- В «МойСклад» всегда только GET, нет POST/PUT/DELETE и нет автоматических изменений D1.
- Ограничения: 5 строк/запрос к списку, один запрос этапов за нажатие, максимум 50 этапов на задание, ограничение ответа, тайм-аут 25 секунд, без автоповторов.
- Никакой периодический воркер Cloudflare, Google Таблица, Ozon или WB не изменялись.

## Что означают числа
- totalAllTime — все документы «Производственные задания» в базе, не текущий портфель.
- documentPosted — факт проведения документа, не завершение изготовления.
- deliveryPlannedMoment — плановый срок, когда он задан в «МойСклад».
- plan — сумма плановых количеств по позициям одного задания, без суммирования каждого производственного этапа повторно.
- finishedFinalStage — сумма выполненного объёма на последнем этапе каждой позиции. Это не отгрузка.
- Если позиции смешивают разные единицы измерения, сложение количеств условно. До получения единиц измерения в UI используются «ед.», а итог нельзя считать количеством комплектов.
- ms_stages_unverified означает неполные/неожиданные данные; нельзя заполнять нулями отсутствующие показатели.

## Известные ограничения и контроль
- Поиск номера через API filter=name=... требует фактического подтверждения на реальном задании после публикации.
- Пять последних и постраничный список — не список всех незавершённых. Критичные задания из прошлых дат надо открывать отдельно по номеру.
- Исполнители швей/ОТК, сроки отдельных операций, остатки материалов и контроль задержек по всем активным заданиям здесь ещё не подтверждены.
- На одно задание более 50 строк этапов предусмотрен отказ с безопасным кодом, а не неполный итог.
- Контрольная точка: №00737 на 20.11.2026 — план 3, заключительный этап 0, пять этапов по нулю (проверено владельцем). Сравнить после изменений.
- Полный производственный контур (заказ покупателя → задание → выполнение → готовая продукция/отгрузка) разрабатывать только после сверки схемы данных, без двойного учёта.

## Откат
При ошибках откатить только последнее изменение в ветке feature/marketplace-agents-staging / Cloudflare Pages. Не вращать токены, не откатывать данные D1 и не затрагивать WB/Ozon.


## Поэтапная сверка незавершённого производства (аудит страницы)
- Кнопка «Проверить 5 заданий» запускает вручную, только при открытом разделе, до пяти последовательных GET вызовов существующего owner-only /api/ms/production-stages?taskId=UUID для видимых документов (при точном поиске может быть один).
- Расчёт для проверенного задания: plan - finishedFinalStage > 0 ⇒ незавершено; = 0 при непротиворечивом выполнении каждого этапа ⇒ завершено; иначе не подтверждено.
- firstUnfinishedStage — первый этап с done < plan по агрегированному результату. Это диагностический признак, не подтверждение фактической очереди/ответственного.
- Три состояния строго раздельно: незавершено, завершено, не удалось подтвердить. Ошибки/отсутствующие строки не превращаются в ноль.
- Статистика и таблица только текущей страницы; при переходе на другую страницу очищаются. Нет таблицы или постоянного хранилища проверок, нет полной сводки 740 документов.
- Если вкладка закрыта во время проверки, новые запросы не начинаются после завершения текущего. Запросы выполняются последовательно, без автоповторов.
- Цель следующего этапа: обоснованная автоматическая сверка всей незавершёнки по API с контролем полноты и нагрузки, только после оценки оптимальных фильтров. Сейчас нет доказательства серверного фильтра, возвращающего все незавершённые документы одной выборкой.


## Контроль прошедшей плановой даты — безопасный этап
- В ручном аудите текущей страницы показывается плановая дата задания и индикатор «Плановая дата прошла». Критерий: этапы подтверждают незавершённость, плановая календарная дата уже закончилась по часовому поясу Europe/Samara.
- Дата и время API «МойСклад» считаются московскими, отображаются по Самаре; сравнение проводится **по дню**, не по часу. День текущей даты не считается просроченным. Это не подтверждение нарушения договорного SLA и не оценка ответственности швеи.
- Если этапы не удалось проверить, нет даты или дата некорректна, просрочка не заявляется; завершённые задания не считаются просроченными задним числом.
- Число «Плановая дата прошла» — только среди подтверждённо незавершённых заданий **текущего ручного аудита** (до пяти документов). Данные не сохраняются, автоматически не отправляются, не суммируются между страницами.
- Новые обращения к API не добавлены, право на запись в «МойСклад» не запрашивается, отчёты Ozon/WB и таблицы не изменяются.
- Следующий этап — после замера фильтров и нагрузки API построить отдельную выборку всех незавершённых заданий с доказуемой полнотой; до этого не называть постраничную проверку полным производственным портфелем.

## Диагностика полного охвата (ручная, без сканирования)
- Защищённая кнопка «Оценить объём API» выполняет **не более двух последовательных GET**: список заданий (`productiontask`) и этапы **только одного задания** (`productionstage`) с обязательным фильтром `productionTask`. При отсутствии заданий второй запрос не нужен.
- Подтверждается только общий счётчик заданий и количество этапов в одном образце задания; общее число этапов **неизвестно**, получить его прежним нефильтрованным запросом нельзя (HTTP 412 от 20.11.2026).
- Диагностика не перебирает задания, не считает готовые комплекты, не определяет незавершённые и не включает фоновый мониторинг. Наличие ссылки в одном образце не доказывает охват всех записей.
- Ограничение размера ответа — 64 КиБ на каждый запрос, нет автоповторов и нет записи в D1, Git или API «МойСклад».
- Контракт дальнейшего полноценного сканирования, проверка полноты и нагрузки: [ms-production-coverage-plan.md](ms-production-coverage-plan.md).

## Пульт контроля конкретных заданий — приоритетная пятёрка

В рамках 90-дневного плана CTO после пульта «последние 10» добавлен блок **«Задания в работе · контроль по номерам»**. Он работает с настоящими номерами производственных заданий, которые руководство цеха указало вручную (до 5 номеров через запятую или строку). Это позволяет видеть давно созданные задания, не попадающие в топ последних 10, **без обхода 744 исторических документов**.

- Один ручной запуск: до пяти точных `GET /api/ms/production-feed?number=N` и до пяти `GET /api/ms/production-stages?taskId=UUID`, строго последовательно, **пауза 2 с между запросами**; максимум 10 GET.
- Поиск документа проверяет `selection=EXACT_DOCUMENT_NUMBER_NOT_ACTIVE_TASKS`, совпадение исходного номера и `totalMatching=1`, наличие ID. Несколько документов с одним номером — отказ, а не произвольный выбор.
- Проверка этапов использует ранее подтверждённый анализ смешанных производственных цепочек по позициям. Только подтверждённый незавершённый этап с завершившимся плановым днём Самары может получить отметку «Плановая дата прошла».
- Отсутствующее задание, невозможность проверить этапы или плановую дату **не считаются выполненными, нулевыми или отгруженными**. При 401/403/429/ошибке upstream весь текущий ручной обход останавливается, частичная сводка не публикуется.
- Из той же сессии можно открыть точный номер в существующем просмотре и выгрузить локальный CSV для старшей производства. Выгрузка безопасна от инъекций формул таблицы и **не** является импортом или назначением задачи.
- Номера и результаты в облачной БД не сохраняются, доступна кнопка остановки, никаких повторных или фоновых запросов. Без owner-сессии существующий API блокирует чтение.
- Для настоящей **полной очереди незавершённых** необходимо определить единый подтверждённый источник активных заданий (график производства/заказы с фактическим этапом), договориться о связи с заданиями и исполнителями, а затем выстроить дозированную синхронизацию. Не считать подбор 5 задач полной планёркой цеха.
- Последующие обязательные gates: фактические исполнители, техкарты по SKU, раздельные остатки основных и внешних материалов, резерв под заказы, готовая продукция и журналы перемещений. Пока этих подтверждений нет, системы дефицита «хватит на N комплектов» **не включать**.

**Приёмка:** unit/UI тесты, owner-only, имитация пяти заданий с разными этапами и прошедшей датой, ошибка 429, отмена, полная неопределённость, CSV; затем успешный CI, staging deploy, публичный smoke HTML/JS 200, анонимный API 401. Для реальной проверки владелец или старшая производства вносит номера до 5 **фактически активных** заданий.

## Автоматическая проверка при открытом офисе — версия без ручного ввода

По запросу владельца «не вводить номера заданий и не нажимать кнопки» основной пульт переведён с ручного режима на **автоматический при открытой вкладке**:

- `GET /api/ms/production-feed?sort=updated` и `?offset=5&sort=updated` используют проверенное документированное `order=updated,desc` и возвращают **10 недавно обновлённых** документов; это не доказанный набор **всех активных** заданий. Названия/номера пользователь не вводит.
- Для каждого документа до одного `GET /api/ms/production-stages?taskId=...`. Всего максимум 12 последовательных защищённых API запросов при сканировании, с паузами по 2 секунды; отказ на 401, 403, 429, неполных ответах. Обновление при входе на раздел `#production` и при возвращении вкладки, но не чаще одного раза в 30 минут; при скрытой вкладке новых запросов нет.
- Первые 10 строк общего складского отчёта также загружаются при открытии раздела и обновляются не чаще одного раза в 30 минут, в том числе когда пользователь не нажимает «Обновить остатки».
- Переключение категории в уже загруженном списке не запрашивает API. Ручной ввод номеров сохранён **только в закрытом блоке «Дополнительно»** для экстренного аудита, он больше не нужен для обычного пользования.
- Нет новых POST, PUT, PATCH, DELETE ни в МойСклад, ни в D1. Не включать клиентский/серверный массовый обход 744 исторических документов и не утверждать полный список незавершёнки, пока нет фонового дозированного сканера с контрольной полнотой.

**Ограничение:** браузерный автоматический режим работает при открытом разделе и действующей owner-сессии. Он **не** равнозначен серверному 24/7 мониторингу. Чтобы офис функционировал при выключенном компьютере, требуется отдельный Cloudflare Worker Cron с D1, владеющий собственным безопасно хранимым MS_API_TOKEN. Это самостоятельный следующий этап, который нельзя считать запущенным лишь по GitHub-мержу Pages.
