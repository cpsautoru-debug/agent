# АвтоСклад63 — объединённый выбор 36 SKU Ozon в журнале связей с WB

## Проверенная исходная картина

По подтверждённому экрану 22.11.2026:
- Ozon Profit — 36 уникальных SKU с действующими версиями себестоимости;
- вспомогательный справочник товаров — 3 SKU;
- владелец вручную запустил точечный поиск Ozon Seller API для 33 отсутствующих SKU, найдено 33 / 33, необнаруженных 0;
- среди найденных — разные комплектации Priora, Vesta и дверные карты; одинаковые модели не означают одинаковую себестоимость.

## Что делает обновление

Раздел «Финансы WB» → «Подтверждённые связи товаров WB ↔ Ozon» → кнопка «Загрузить товары и связи»:
1. Проверяет текущие подтверждённые связи, актуальные артикулы WB и 3 SKU из вспомогательного справочника Ozon.
2. Если `cost-audit.skuCoverage.profitOnlySkuCount > 0`, запрашивает по одному списку отсутствующих SKU реальные названия и `offer_id` через уже существующий owner-only `GET /api/finance/ozon-sku-cards`. Только после явного нажатия — никакого автоматического маркетплейс-поллинга.
3. Объединяет найденные SKU с тремя локальными, исключая уже привязанные к WB и не дублируя карточки. Сохранять себестоимость или регистрировать вымышленный товар не требуется.
4. Если Seller API недоступен, показывает только локальные SKU и явное предупреждение.

При выборе SKU, которого нет в локальной таблице `ozon_cost_entries`, owner-only `POST /api/finance/product-links`:
- проверяет наличие выбранного WB артикула в завершённых финансовых отчётах;
- проверяет, что выбранный SKU существует в проверенном версионном документе `costs` Ozon Profit;
- повторно читает **точно одну** карточку SKU из подключённого Seller API;
- подписывает HMAC предпросмотром найденные `name` и `offer_id` вместе с подтверждениями владельца, датой и основанием идентичности;
- при сохранении повторяет проверки, блокирует изменённую карточку или поддельный токен и делает только атомарный INSERT одной связи в **ранее созданную** неизменяемую таблицу `office_finance_product_links`.

Существующая таблица связей хранит поле `model_name` максимум 100 символов. Для пути Seller API оно содержит **сокращённое реальное название карточки**, а не выдуманную модель. Полное название показывается при предпросмотре и участвует в подписи. Это уточнено в интерфейсе.

## Границы

- Сохранённая связь = подтверждение владельцем одинакового физического изделия; **не автоматическое перенос себестоимости** между WB и Ozon.
- Не изменяется `ozon_cost_entries`, ни один реестр себестоимости, Ozon Profit D1, исходный WB, рекламные расходы, налоги, текущие синхронизации и Cron.
- Новые SQL миграции и новые API токены **не требуются**.
- Не связывать товары по одной модели без проверки кроя, материалов, цвета, комплектации.
- Источники Seller API принадлежат **подключённому Ozon кабинету**; архивные и сторонние товары не могут считаться идентичными автоматически.

## Приёмка

Открыть `https://autosklad63-office-staging.pages.dev/#wbFinance`, обновить страницу, раскрыть «Подтверждённые связи товаров WB ↔ Ozon» и нажать «Загрузить товары и связи». Должно отобразиться 36 доступных SKU Ozon (при сохранении источников 33 + 3), каждый с названием/кодом, и 54 артикула WB за вычетом уже связанных. Не нажимать «Подтвердить и сохранить», пока физический товар не проверен.
