# АвтоСклад63 — подтверждённые связи WB и Ozon

Релиз 21 ноября 2026, только staging. Без использования Codex.

## Назначение

Один подтверждённый физический товар может иметь разные артикулы WB и Ozon. До подтверждения нельзя переносить между площадками его себестоимость. Реестр сохраняет только связь и дату проверки, не цены.

Рабочий процесс:
1. Войти владельцем в раздел Финансы · WB.
2. Раскрыть «Подтверждённые связи товаров WB ↔ Ozon».
3. После миграции нажать «Загрузить товары и связи».
4. Выбрать **реальный** артикул из завершённых WB Finance API отчётов и SKU из сохранённого Ozon справочника.
5. Сверить **материал, лекала, комплектацию, фото и изделие**. Ввести проверенную дату и текстовое основание без выдуманного номера техкарты.
6. Подтвердить две отметки (идентичность и запрет автоматического переноса стоимости).
7. «Проверить связь» — signed 10-minute preview, никаких записей.
8. «Подтвердить и сохранить связь» — один атомарный INSERT и повторная проверка источников.
9. После успешной записи связь появится в журнале, соответствующие коды станут недоступны для повторного связывания.

## Однократная миграция — отдельная staging Pages D1

Плагин Cloudflare не получил d1.read/d1.write (401). До появления прав SQL нужно выполнять вручную. **Не трогать** WB Finance D1, отдельную Ozon Profit Worker D1 и производственные базы.

- В Cloudflare открой Pages проект **autosklad63-office-staging** → Settings → Bindings.
- Найди привязку **OZON_FINANCE_DB** и запиши **точное имя D1 из этой строки**.
- Открой именно эту базу в D1 → Console.
- Скопируй полный текст `migrations/0005_finance_product_links.sql` в исходной ветке `feature/marketplace-agents-staging` (после мержа). Файл начинается сразу с `CREATE TABLE`, без комментариев `--`, чтобы вставка в одну строку не превратилась в комментарий.
- Выполни SQL один раз. Затем отдельно выполни:

```sql
SELECT name FROM sqlite_master WHERE type='table' AND name='office_finance_product_links';
```

Ожидается **одна строка** `office_finance_product_links`. Повторный запуск только после проверки состояния, не вслепую. SQL добавляет таблицу и индексы; не обновляет существующие товары, финансовые операции, себестоимости или Worker/Cron.

## Защиты

- Авторизация владельца Google + D1 owner, привязка учётной записи WB.
- CSRF: POST только с Origin `https://autosklad63-office-staging.pages.dev`, JSON.
- Проверяются точные WB vendor_code по реально завершённым финансовым отчётам и Ozon SKU по действующему `ozon_cost_entries`.
- Подписанный preview привязан к владельцу, кодам, дате, основанию, найденному артикулу продавца и модели Ozon. Токен действует 10 минут.
- Одно-ко-одному: WB vendor_code PRIMARY KEY; Ozon SKU UNIQUE; INSERT не заменяет чужую запись.
- UPDATE и DELETE запрещены триггерами, коррекции требуют отдельной аудированной миграции.
- Линк не содержит суммы себестоимости, не увеличивает прибыль и не изменяет запись WB, Ozon, МойСклад.
- Если миграция отсутствует, GET сообщает `migration_required`, POST запрещён.

## Дальнейший порядок

После первичных подтверждённых связей — отдельный версионный master-catalog себестоимости с правилом действия по дате, реестр затрат на рекламу, налоговые события по собственным налогоплательщикам и детальные общие расходы (упаковщик, водитель, ОТК, управляющий, аренда, мусор, связь). Не переносить без подтверждения цену по всем артикулам одной модели. Не удваивать расходы, ранее учтённые маркетплейсом.
