# МойСклад — наличие на одном складе без полного обхода каталога

Дата: 20.11.2026. Этап CTO: достоверные складские показатели. Выпуск только в тестовый онлайн-офис.

## Подтверждённая проблема

Скриншот владельца из staging: фильтр «Склад материалов — внешний» по **текущей странице номенклатуры** показал 10 нулей, при общем количестве 359 позиций. Это **не означает**, что внешний склад пуст. Старый фильтр действительно только клиентский — среди первых десяти позиций, он не делает запроса остатков всего склада.

## Отдельный режим «Наличие на выбранном складе»

Официальная схема МойСклад 1.2 содержит:
- \`GET /entity/store?limit=50&offset=0\` — прочитать все доступные склады в пределах 50. Для указанного имени должен быть **ровно один** склад с корректным UUID.
- \`GET /report/stock/bystore/current?stockType=stock&filter=storeId=<UUID>\` — краткий отчёт по одному складу. API возвращает массив \`{assortmentId,storeId,stock}\`; без \`include=zeroLines\` обычно включены только ненулевые позиции.
- \`GET /entity/assortment?limit=10&filter=id=<UUID1>;id=<UUID2>...\` — имена **первых десяти** позиций. Никакого общего каталога или обхода всех позиций на сервере, сортировка в API не обещана.

Источники спецификации: [stock-bystore-current.yaml](https://github.com/moysklad/api-remap-1.2-openapi-specification/blob/master/src/paths/reports/stocks/stock-bystore-current.yaml), [stockCurrentByStore.yaml](https://github.com/moysklad/api-remap-1.2-openapi-specification/blob/master/src/components/schemas/report/stockCurrentByStore.yaml).

**Новый маршрут** \`GET /api/ms/warehouse-availability?store=<NAME>\`: только owner Google session + D1, токен остаётся на сервере, строго проверенное имя склада, максимум **3 последовательных GET**, без автоповтора, redirect или записи. Ограничения: не более 50 доступных складов, до 500 строк текущего отчёта, 256 КиБ, 20 секунд на каждый upstream GET, не более 10 номенклатурных имён. При превышении ограничения — fail-closed (никаких неполных «общих сумм»).

**Отображение:**
- Имя выбранного склада, число строк в кратком отчёте, положительные/отрицательные/нулевые/неизвестные количества, первые 10 названий и физических остатков.
- При превышении 10 позиций явно сообщается количество оставшихся, которые **не отображаются**. Это не топ по продаже или по величине остатка.
- Краткий отчёт НЕ содержит все нулевые позиции и не включает отдельно резерв и ожидание. Это не акт инвентаризации; единицы измерения могут оставаться «Не указана» до официального расширения uom.
- Старый раздел \`stock/bystore\` с физическим остатком, резервом и ожиданием остаётся доступен для точечного поиска номенклатуры.

**Не выполнено:** синхронизация всех 359 позиций в D1, исторические перемещения, дефицит по технологическим картам, готовая продукция, автоматический мониторинг. Реальные документы МойСклад и финансовые данные не изменялись.

## Проверка выпуска

1. CI — owner-only, 3 sequential GET, \`filter=storeId\`, подбор по имени, неизвестные/отрицательные, 429, лишние строки, неподтверждённый склад; без токенов в ответе.
2. Cloudflare staging — новые статические файлы 200 с правильными MIME, анонимный API должен оставаться HTTP 401 JSON.
3. Владелец выбирает «Склад материалов — внешний» и нажимает **«Показать наличие склада» один раз**. Если report current недоступен по тарифу или возвращает неожиданный формат, записать только фиксированный код ошибки и HTTP-статус, не делать массовых повторов. Если ответ успешен — проверить 2–3 позиции по МойСклад и решить, нужна ли следующая пачка.
4. Для единиц измерения сделать отдельную ограниченную проверку расширения \`uom\`. Пока единицы отсутствуют, не считать готовность материалов к раскрою в метрах.

Это следует 90-дневному плану: достоверность → обзор руководителя → контроль дефицита и диспетчер производства → ИИ.

## Результат первого реального чтения — 20.11.2026, 21:15 (Самара)

Владелец подтвердил успешный owner-only GET в staging для `Склад материалов — внешний`:
- **17** позиций с ненулевым учётным остатком, **17 положительных**, **0 отрицательных** и **0 неизвестных** на момент отчёта.
- Первая страница показывает **10** наименований, ещё **7** оставались скрытыми. Это реальные агрегаты из МойСклад, но не физическая инвентаризация и не список нулевых товаров.
- Примеры из снимка: чёрная алькантара — 150; Antara light — 100; тёмно-серый Pegas — 40. Единица измерения на момент снимка **не подтверждена**; считать эти цифры метрами нельзя.

### Доработка просмотра и единиц измерения

- Добавлена **постраничная навигация** первого краткого отчёта по выбранному складу: `page=0..49`, сервер обрабатывает **по 10** позиций на ручной запрос; при 17 позициях страница 2 возвращает оставшиеся 7, а не снова первые 10.
- При открытии следующей страницы вновь читается краткий отчёт выбранного склада; каждая страница **новый моментальный срез**, а не транзакционно согласованный снимок. Если количество изменилось, страница может перестать существовать; API возвращает `warehouse_page_out_of_range`, не выдумывая нули.
- Для десяти названий пробуется `expand=uom` в **одном** `assortment` запросе, чтобы получить название единицы измерения прямо от источника. Если расширение возвращает **ровно HTTP 400**, один раз выполняется прежний names-only запрос; никакие метры, штуки или коды единиц не выводятся по догадке. На 401/403/429, других ошибках повтор запрещён.
- Максимальная нагрузка на одно ручное нажатие — **4 последовательных GET** (склады, краткий отчёт, попытка имён с uom, единичный fallback на HTTP 400); при поддержке expand — **3 GET**. Нет фоновой синхронизации и записи в «МойСклад»/D1/маркетплейсы.
- Первый и второй запросы могут увидеть изменения остатков во время работы. Указанные 17 позиций не превращаются в подтверждённые 17 строк физического учёта.
- Ключевые следующий этап: отдельно классифицировать материал/готовое изделие по надёжному признаку, затем сверить все ненулевые позиции и техкарты, прежде чем считать обеспеченность производства или запускать автоматические рекомендации закупки.

Критерии приёмки: CI всех тестов, anonymous API 401 JSON после выпуска, HTML/JS 200, затем **один ручной просмотр страницы 2** владельцем и проверка реальных `uom` (или честного «Не указана»). Массовый проход всего каталога не включать.
