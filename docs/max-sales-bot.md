# MAX — подключение менеджера продаж

Ответственный: разработчик; приёмка — Антон. Вход: опубликованный бот «АвтоСклад63 менеджер продаж», рабочие чаты и основная Google Таблица. Ожидаемый результат: список превращается в проверяемую заявку, уточнения разрешены, подтверждение уполномоченного сотрудника создаёт запись без дубля.

Бот создан владельцем: id632135065259_2_bot. Модерация подтверждена скриншотом 18.10.2026. Это ещё не подтверждение работающего обработчика.

Первый этап подготовлен на существующем Cloudflare Worker autosklad63-instagram, отдельные маршруты /max/health и /api/max/connection. MAX_BOT_TOKEN владелец вводит как Secret в Cloudflare Settings → Variables and Secrets. Проверка токена использует только GET https://platform-api2.max.ru/me; ответ не раскрывает токен. Диагностика защищена существующим ADMIN_TOKEN. Нельзя ослаблять TLS-проверку при ошибке сертификата. Токен MAX не заменяет INSTAGRAM_ACCESS_TOKEN.

Следующие этапы после проверки доступа:
1. Закрытый список разрешённых рабочих чатов и сотрудников; отдельно определить, кто подтверждает запись. Для группы разрешить добавление бота и назначить минимальные необходимые права.
2. HTTPS webhook с проверкой X-Max-Bot-Api-Secret, подписка только на нужные события. Игнорировать обычную переписку, сообщения ботов и неизвестные чаты. Начинать заявку явной командой «Принять заявку» вместе со списком или ответом на него.
3. Очередь заявок в закрытом хранилище: ID исходного сообщения, версия, позиции, количество к отгрузке, наличие, производство и запас отдельными величинами. Для «завтра» явно показывать абсолютную дату Europe/Samara. Не считать агрегат отдельных продаж маркетплейса заказами с выдуманными ID.
4. При неоднозначности запросить уточнение и показать новую версию заявки. Подтверждение связано с конкретной версией и разрешённым сотрудником; повтор и устаревшая кнопка не создают запись.
5. Постоянный доступ сервера только к рабочей Google Таблице. Коннектор чата не является доступом Cloudflare. Выбрать защищённый мост Apps Script или отдельный Google-доступ; запись в отдельный лист заявок на отгрузку/производство, без перезаписи формул и без автоматического списания материала.

Критерии запуска: проверены разрешённый и посторонний пользователь, повтор события, противоречие количества, запас сверх отгрузки, изменение заявки после подтверждения, ошибка и неоднозначный результат записи; одна заявка записана ровно один раз с проверкой чтением.

Блокеры сейчас: MAX_BOT_TOKEN не введён; чаты и сотрудники не привязаны; webhook, разбор списков, подтверждения и постоянная запись в Google Таблицу ещё не подключены. Нельзя менять статус менеджера на «автономно работает» до приёмки.

Результат следующей проверки 18.10.2026: владелец ввёл MAX_BOT_TOKEN; Worker дошёл до исходящего запроса /me, но получил HTTP 526. Прямой запрос без токена также не прошёл SSL-проверку. Правильность токена не подтверждена и не опровергнута. MAX требует доверия к сертификату Минцифры; Workers не поддерживает пользовательский CA в node:https. Отключать проверку TLS и пересылать токен через сторонние прокси нельзя. Для следующего теста нужен Node.js/Python-обработчик с официальным CA, доверенным только для MAX. Возможный бесплатный тестовый хостинг — Render Free: засыпает после 15 минут простоя и имеет ограничения; локальный диск непостоянный, очередь хранить снаружи. Это не обещание непрерывной производственной работы.

Документация API: https://dev.max.ru/docs-api и https://dev.max.ru/docs-api/methods/POST/subscriptions .

Подготовлен apps/max-agent — отдельный Node.js-обработчик для Render Free. Публичные сертификаты загружены с официального HTTPS-источника Госуслуг, проверены как CA и по сроку действия. Они используются только для platform-api2.max.ru; системное хранилище не меняется. Проверка реального API с заведомо неверным тестовым токеном вернула HTTP 401: TLS проходит. Действительный токен на Render ещё должен ввести владелец. На данном этапе /api/connection проверяет только бота, не читает сообщения и не пишет в таблицу. Три теста сервиса пройдены.
