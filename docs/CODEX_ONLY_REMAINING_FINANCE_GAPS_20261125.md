Дата: 2026-11-25. Рабочая ветка: `feature/marketplace-agents-staging`. Staging: https://autosklad63-office-staging.pages.dev/

## Рамки полномочий
Владелец **явно разрешил выполнять все необходимые действия по настройке и проверке своего онлайн-офиса без повторных согласований**, включая работу с GitHub и Cloudflare, чтение подключённых Seller API, безопасные изменения кода и публикацию. Не спрашивать у владельца разрешений на каждый обычный шаг и тест, не просить повторно предоставлять уже подключённые API-ключи. При этом не обходить аутентификацию, уровни доступа и ограничения API; не выводить секреты в логи/чат/GitHub. Никаких действий с деньгами/ценами/остатками или необратимых изменений без отдельной явно относящейся к ним авторизации.

**Только задачи, которые не удалось завершить инструментами ChatGPT GitHub/Cloudflare:** доступ к авторизованной сессии офиса для выполнения защищённых API, работа с локальной средой и запуск минимальных локальных тестов/сборки. Всё остальное уже сделано и не должно повторяться.

## Суть не закрытых задач — выполнять по порядку, одним проходом
1. **Под авторизованной сессией владельца** прочитать `/api/yandex/direct-cost-review?month=2026-10` и `/api/finance/cost-audit?month=2026-10`. В случае отказа или кода `incomplete_cost_coverage` получить точные `missing`, `issues`, `blockers` из результатов; выполнить адресное исправление причин в нормализаторе/маппинге на основании официальных API карточек/реализаций и уже известного owner's cost reference. НЕ подставлять цену по сходству модели или из каталожного purchasePrice. Проверить отчет каждого из двух магазинов, включая `NO_DATA` (не считать его нулём без дополнительного источника).
2. По WB в защищённом API получить **полный валовый доход** для объекта АУСН «Доходы» за октябрь, включая 10/10 отчётов и корректное отражение возвратов/взаимозачётов. Не использовать `for_pay` либо `bank_payment_kop` как налоговую базу. Девять сохранённых XLSX содержат только `MANUAL_ESTIMATE` / `ASSUMED`; их налог 106 477,53 ₽ нельзя признать полным.
3. По Ozon проверить категорию «Баллы за скидки», компенсации, погашения, возвраты, доходы по налоговым датам — реальная валовая база может отличаться от 1 764 549,43 ₽. Использовать Seller/Performance API, а не эвристическое сложение любых одноимённых начислений.
4. В Яндексе согласовать валовые заказы, фактическую реализацию, возвраты, услуги, оплату, скидки и COGS **по уникальным orderId+shopSku**, 2 магазина одного ИП. Не вычитать повторно услуги и логистику, уже включённые в «после услуг». Получить единый проверенный для октябрьского управленческого P&L результат.
5. В общей панели `#dashboard` / `business-pnl.mjs` вывести ясные статусы каждого источника и единую налоговую базу ИП. Финальный менеджерский итог вычислять только когда 3/3 канала и единая АУСН 8%-база подтверждены по API, без бухгалтера и банковских выписок, с проверкой одинаковых периодов. Иначе показать конкретно **какая сумма отсутствует**. Ноль вместо неизвестных сумм запрещён.
6. Проверить пригодность подходов из [PCDCK/ozon-mcp](https://github.com/PCDCK/ozon-mcp) (надёжная пагинация/429/проверка схем/сверка Ads) и [theYahia/wildberries-mcp](https://github.com/theYahia/wildberries-mcp) (по-хостовые лимитеры, 409 штраф, requestId). Применять отдельные небольшие приёмы, но не устанавливать сторонние MCP целиком и не передавать им секреты.

## Проверки и результат
- Только минимальные адресные проверки синтаксиса/контрактов и один end-to-end проход на staging под владельцем. Не устраивать миллион тестов.
- Не изменять подтверждённые исторические себестоимости и суммы без точных операций и source trace.

- Отчёт: URL опубликованного офиса, commit, по каждому каналу сумма/coverage, вычисленный единый АУСН (если база полная) или точные оставшиеся пробелы; нуль незаполненных значений не допускается.
- **Не сообщать «всё завершено», если данные этого не подтверждают**. Не просить пользователя повторных одобрений; действовать на основе предоставленного разрешения.
