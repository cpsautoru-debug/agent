## Изучены внешние MCP репозитории
- https://github.com/PCDCK/ozon-mcp (MIT, Python, Seller/Performance API): README описывает 466 методов, 15 MCP инструментов, 13 готовых workflows. Для нас полезны сценарии синхронизации финансов, возвратов, рекламы; проверка JSON-схем, пагинация offset/cursor/last_id/page, исключение повторяющегося курсора, 429 Retry-After, диагностика лимитов подписки. SECURITY.md — env-секреты, read-only по умолчанию на нашей стороне.
- https://github.com/theYahia/wildberries-mcp (MIT, TypeScript, 30 инструментов): категории Seller API маршрутизируются на разные хосты. В src/rate-limiter.ts конкретно реализованы per-host token buckets и обработка 409 через X-Ratelimit-Retry-After; src/client.ts содержит timeout и error/requestId. Есть reportDetailByPeriod, возвраты, реклама, платное хранение.

**Решение:** не встраивать оба сторонних MCP целиком в Cloudflare Pages/Workers. Наш офис на JS+Cloudflare D1 имеет действующие API-источники. Переносить проверенные приёмы в собственные ограниченные read-only интеграции, не передавать токены на сторонние серверы. Прямые write-инструменты (цен, запасов, поставок, ответов) не нужны для финансового закрытия.

## Условия итоговой управленческой прибыли
Требуются расчетный послеуслужный вклад Яндекса и себестоимость с возвратами; полная валовая АУСН база WB по всем 10 отчётам; классификация бонусов Ozon; внешняя реклама по всем каналам и однократный вычет общих расходов. Неизвестный источник => null, а не 0. Пока общий итог показывать как "неполный", а не объявлять точной чистой прибылью.
