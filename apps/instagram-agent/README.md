# Собственный помощник Антона

Первая рабочая версия сервера и панели. Не требует BotHelp, Manychat, npm-пакетов или подписки на конструктор. Нужен Node.js 22.9+ (проверено на 24.19).

## Открыть на Windows

Двойной щелчок по «Открыть помощника.cmd». Он запускает локальный сервер в фоне и открывает браузер. Node используется установленный в окружении Codex, либо доступный в системе. Вход защищён случайным ключом, который хранится в data/admin-token.txt. Обычный запуск автоматически подставляет его в панель. Если открывается форма входа — введите ключ из файла. Не публикуйте этот ключ.

Если предпочитаете обычный запуск: `node --env-file-if-exists=.env server.mjs`, затем http://127.0.0.1:8766. Для остановки запущенного в терминале процесса — Ctrl+C. Кнопка «Приостановить всё» блокирует обработку и отправку, но не останавливает сервер. Фоновый процесс можно завершить через диспетчер задач, проверив путь команды server.mjs именно этой папки.

Файловая страница dashboard.html отдельно не работает: для панели нужен сервер. Старый демонстрационный index.html находится в другой папке и не является этой системой.

## Что работает

- База ассортимента и цен в knowledge.json; цены не дублируются в коде.
- Панель владельца: проверка вопросов, черновики, редактирование перед отправкой, отклонение, общая пауза и пауза диалога.
- Приём подписанных событий Meta на /webhook; проверка принадлежности аккаунту.
- Очередь, история, защита от повторной обработки, отклонение устаревших черновиков при новом сообщении.
- Отдельные запросы для ответа в директ и публичного ответа на комментарий. В этой версии обрабатываются только верхнеуровневые комментарии, не ветки ответов.
- После обнаружения собственного сообщения из Instagram диалог ставится на паузу. Эхо отправки самого агента фильтруется по возвращённому Meta идентификатору. Реальные события нужно подтвердить при интеграции.
- По умолчанию отправка выключена. Даже при её включении тестовые сообщения нельзя отправить.
- Неоднозначный результат отправки, например обрыв сети, помечается «Результат неизвестен» и не повторяется автоматически. Нужно проверить Instagram вручную.
- Максимум 30 попыток отправки в сутки по UTC по умолчанию, конфигурируемый предел до 100. Это ограничение приложения, не гарантия соблюдения всех лимитов Meta.
- По желанию — генерация черновиков локальной моделью через Ollama. Любой такой черновик требует ручной проверки.

## Что НЕ подключено

18.10.2026 создано приложение Meta Autosklad63 Assistant (ID 1911481683155649), Instagram-приложение Autosklad63 Assistant-IG (ID 28650265974635224); аккаунт toxraa принял приглашение тестировщика. Разрешения на переписку, рабочий токен, публичный HTTPS-адрес и облачная модель ещё не подключены. Никакие реальные входящие не прочитаны, ответы клиентам не отправлены. Наличие заполненных параметров в панели не означает подтверждённого подключения.

Демонстрационный режим без модели использует типовые ответы по словам; он не понимает все сложные вопросы. Результаты ИИ также могут ошибаться, поэтому они остаются черновиками. Вложения передаются человеку. Оплата и оформление заказа внутри приложения не реализованы.

## Включить локальный ИИ

1. Установить Ollama с https://ollama.com/ и выбрать модель, подходящую по памяти компьютера и качеству русского языка. Установка и загрузка модели здесь не выполнялись.
2. Проверить модель в Ollama.
3. Скопировать .env.example в .env и указать установленное имя в OLLAMA_MODEL.
4. Перезапустить сервер. Он обращается только к http://127.0.0.1:11434/api/chat. Для удалённого сервера Ollama должен работать на том же сервере. Внешний облачный поставщик ИИ в этой версии не настроен.

Для работы при выключенном компьютере нужен постоянно включённый сервер; для локальной модели на сервере нужны соответствующие ресурсы. Бесплатность работы на любом хостинге не предполагается.

## Подключить Instagram — оставшийся обязательный этап

1. Получить доступ к кабинету Meta for Developers и создать приложение, поддерживающее Instagram API with Instagram Login. При проверке 18.10.2026 кабинет показал страницу входа; доступ к приложениям не подтверждён. Установка этого кода не решает вопрос доступа к Meta.
2. В кабинете приложения подключить Instagram Login и необходимые разрешения: instagram_business_basic, instagram_business_manage_messages, instagram_business_manage_comments. Проверить требования Meta к тестовым ролям, доступу, проверке приложения и использованию в своём сценарии.
3. Авторизовать существующий профессиональный аккаунт toxraa через официальный процесс Meta. Эта версия не содержит готового OAuth-интерфейса: получить и обновлять токен нужно через инструменты Meta. Токен, секрет и идентификатор аккаунта внести только в .env.
4. Указать META_API_VERSION согласно кабинету и действующей документации. Версия специально не выбрана автоматически.
5. Разместить приложение за HTTPS reverse proxy на принадлежащем владельцу сервере. По умолчанию сервер слушает только 127.0.0.1, прокси должен передавать исходное тело webhook без изменения. Не открывать административную панель публично без HTTPS; предпочтителен отдельный доступ через VPN/ограничение по IP. /health не содержит секретов, /api требует токен.
6. В Meta настроить callback https://ваш-домен/webhook и такой же META_VERIFY_TOKEN, как в .env. Подписать именно свой Instagram-аккаунт на нужные события; проверить разрешённые поля в кабинете.
7. Проверить реальные события личного сообщения и комментария, эхо ручного ответа, паузу, доставку одного проверенного ответа. Форматы покрыты тестовыми примерами, но реальные события Meta и выдача разрешений ещё не проверены.
8. Оставить AUTO_REPLY=false. После проверки вручную можно поставить ALLOW_SEND=true для кнопки отправки. Только после успешной проверки разрешается AUTO_REPLY=true для готовых FAQ; сгенерированные моделью ответы остаются ручными.

Приложение консервативно отказывает в отправке через 24 часа от события (включая комментарии). Это собственный предел первой версии, а не утверждение, что правила комментариев и директа одинаковы. Холодные сообщения и личные ответы на комментарий не реализованы. Повторные попытки получения/обновления токена и диагностика прав в этой версии не автоматизированы.

## Данные и эксплуатация

История содержит тексты входящих и черновиков. Она сохраняется в data/state.json без шифрования; ограничьте доступ к папке и резервным копиям. Сохраняется полная история событий за срок хранения, в панель возвращаются последние 100. Это не полноценная переписка: ручные ответы владельца ставят паузу, но их текст не сохраняется, а локальной модели передаются только последние входящие. Записи старше 30 дней удаляются при запуске. Постоянная онлайн-очистка, экспорт/удаление конкретного клиента, мониторинг истечения токена и оповещения о сбоях пока не реализованы.

Запускать только один экземпляр с одним data-каталогом: хранилище рассчитано на небольшой поток, один процесс и локальный диск, не на несколько серверов. Секреты хранятся в .env, исключены из Git и не выдаются API панели. До реального запуска нужны свой HTTPS-домен, резервное копирование, автозапуск процесса, проверка форматов настоящих событий и работающего права отправки. Панель показывает факт передачи человеку, но отдельные уведомления в Telegram не подключены.
