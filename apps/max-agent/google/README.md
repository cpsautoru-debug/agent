# Google-мост заявок MAX

Ответственный: разработчик; приёмка и Google-разрешение — Антон. Вход: команды владельца из привязанной группы MAX. Результат: черновик в «MAX — очередь», после подтверждения — позиции в «Заявки MAX». Критерий: проверена реальная тестовая заявка и повторное подтверждение без дубля.

Код MaxBridge.gs устанавливается в отдельный standalone-проект Apps Script. Веб-приложение использует openById: Google требует стандартный scope spreadsheets; это шире доступа к одному файлу. В коде жёстко закреплён только ID рабочей таблицы, а маршруты ограничены ping/draft/confirm. Не расширять права существующего проекта контролёров; Google-разрешение этого нового проекта подтверждает владелец.

1. Сохранить код, в свойствах скрипта добавить MAX_OWNER_ID и MAX_WORK_CHAT_ID из закрытых настроек Render. Значения не публиковать.
2. Владелец запускает prepareMaxBridge и подтверждает Google-разрешение. Функция проверяет рабочую таблицу и создаёт MAX_BRIDGE_KEY в Script Properties. Секрет не выводится в журнал.
3. Владелец публикует Web app: execute as me, доступ Anyone. Это открывает адрес приёмника, но каждый POST требует HMAC-SHA256, актуального времени и правильных owner/chat; GET не выдаёт данных. Перед публикацией подтвердить именно этот режим доступа. Сама таблица не становится публичной.
4. URL /exec вводится на Render как SHEETS_BRIDGE_URL; секрет из Script Properties — как SHEETS_BRIDGE_KEY. Ввод и сохранение секрета выполняет владелец. В чат и Git его не передавать.
5. После перезапуска Render подписывает ping; до успешного ответа автоматический приём выключен. Даже после включения каждая запись требует /confirm от владельца из рабочей группы.

Команда в группе:

    Принять заявку
    1) Тестовый товар A — 2 шт. (примечание)
    2) Тестовый товар B — 1 шт.

Бот присылает полный черновик владельцу в личный диалог и команду /confirm ID ВЕРСИЯ, которую владелец отправляет в рабочую группу. Если есть нераспознанные строки, повтор номера или дополнительное изделие через «+», подтверждение запрещено: исправить список и отправить заново. Наличие, производство, запас и слова «завтра» сохраняются как исходные примечания; этот модуль пока не интерпретирует их и не создаёт складских операций. Для однозначности указывать абсолютную дату в примечании. Цены и оплаты не выдумываются.

Повтор одного MAX-события определяется по message ID. Полностью одинаковый текст в течение 24 часов считается повтором той же заявки; если нужны две отдельные одинаковые отгрузки, их следует различать в примечании номером партии. Ранее созданный черновик не перезаписывается. Подтверждение сверяет версию и существующие строки. При частичной/ручной правке записей обработка останавливается. ScriptLock сериализует запросы моста, но не блокирует ручное редактирование пользователями; служебные поля очереди вручную не менять.

Ограничения: до 50 позиций, 10 000 символов исходного списка, 5000 строк в каждом служебном листе. Архивирование выполняется отдельно владельцем; код сам ничего не удаляет. JSON очереди и строки с клиентскими данными не копировать в GitHub. Нет авто-публикаций, платежей, изменения цен и списаний. Перед эксплуатацией проверяется реальный цикл MAX → Google → повтор команды, а не только локальные тесты.
