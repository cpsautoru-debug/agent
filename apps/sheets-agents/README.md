# Контролёры учёта АвтоСклад63

Три выполняемых проверяющих модуля Google Apps Script: продажи, склад и финансы. Это проверки по правилам, не языковая модель. Бесплатный запуск внутри рабочей Google Таблицы в пределах квот Apps Script. Внешние API, сервер, ключи и токены не используются.

## Установка

1. В рабочей таблице открыть **Расширения → Apps Script**. Создать отдельный файл `OfficeAgents.gs`, сохранив существующий код проекта.
2. Вставить весь `Code.gs` из этой папки и сохранить. Если в проекте уже есть `onOpen`, объединить создание меню с существующим обработчиком, не оставлять два обработчика с одинаковым именем.
3. Выбрать функцию `runOfficeAgents` и нажать **Выполнить**. Владелец лично разрешает Google доступ только к текущей таблице. Нет доступа к почте, внешним запросам и платежам.
4. После успешного запуска появятся **Отчёты контролёров**, **Журнал контролёров**, **Состояние контролёров**. Проверить ID и время запуска. Ошибка отдельной роли записывается отдельно.
5. После перезагрузки таблицы доступно меню **АвтоСклад63 — контроль**. По умолчанию запуск ручной. Если позже нужен запуск без открытой таблицы — владелец может создать временной триггер для `runOfficeAgents` в редакторе Apps Script; расписание пока не установлено.

## Поведение

- Читает Заказы, Остаток, Отгрузка. Проверяет схему заголовков и целевую таблицу. Лимит источника — 5000 строк: превышение выдаёт ошибку, данные не усекаются.
- Не меняет бизнес-данные, формулы, цены, статусы заказов, резервы или списания. Не отправляет сообщений.
- Отчёты и состояния — снимок последнего запуска; эти служебные листы полностью принадлежат модулю. Не вносить в их строки ручные данные. Журнал накапливается; при достижении 10000 строк требуется ручное архивирование.
- Документная блокировка предотвращает параллельные запуски этого модуля. Она не блокирует ручное редактирование людьми: отчёт отражает прочитанные данные во время проверки, не транзакционный снимок всех листов.
- Дата проверяется в часовом поясе таблицы. Успешное выполнение не означает отсутствие замечаний, фактическое наличие и полноту учёта.
- При неудачной записи Google может оставить часть служебного отчёта. Сопоставлять ID запуска во всех трёх листах; не считать старое состояние подтверждением нового запуска.

## Статус подключения

Код установлен в связанный Apps Script; первый реальный запуск подтверждён журналом и состоянием всех трёх ролей 17.10.2026. Запуск ручной, расписание не установлено. Статус внутри сайта пока не синхронизируется: Sites-коннектор для чтения таблицы в опубликованном приложении недоступен в текущем наборе инструментов. Не публиковать таблицу и не выдавать её токены ради обхода этой границы.

Проверки алгоритмов: `node --test test.mjs`. Они не подтверждают авторизацию или реальный запуск в Google.
# Обновление проверок чехлов и ковров

Контролёры продаж и финансов проверяют оба листа: «Заказы» и «Заказы ковры». Источник замечания сохраняет имя листа. ID позиции должен быть уникален между листами; отгрузки проверяются один раз. Отсутствующий или изменённый источник приводит к ошибке проверки, а не к успешному неполному отчёту.

Изменение исходников GitHub не обновляет автоматически уже установленный Google Apps Script. Обновление скрипта, его запуск и установка расписания выполняются отдельно после разрешения владельца; до этого новая логика считается подготовленной, не запущенной.
